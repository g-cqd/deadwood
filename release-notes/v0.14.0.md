# deadwood 0.14.0 (from 0.13.1)

The index path reports what it used to miss and no longer reports what only a `#Preview` uses. Four causes, all with
`--index-store-path`; without a store the findings are those of 0.13.1. On the reference app with the Xcode store of the
"the reference app Develop" scheme, 68 findings became 118 (35 more in production code, 21 more in test targets, 6 fewer).
analyzerkit is still `d76118d`.

## Report

- `skippedFiles` lists the files the store does not describe, with the reason `notIndexed` or `changedSinceBuild`

## Findings that may appear

All with `--index-store-path`:

- A function or method that takes a parameter and that nothing calls. The parameter used to keep it alive, and the type
  of any initializer with a parameter. On the reference app: `ConnectionManager.asyncMessageStream(for:)`,
  `PictureInPictureView.minimizePip`, `BottomSheet.contentCenterPosition` and others.
- A type that nothing creates and whose members only refer to each other or are `@Published`
  (`PictureInPictureCallViewModel`), reported as used only by dead code.
- Declarations in a file the store has no unit for (a target the scheme does not build, test support), judged by name
  over every file: a name any file uses keeps all its declarations alive. On the reference app: `ErrorMock` and 20 more, all in
  test targets.
- A property that is only written (`CameraVideoSource.desiredResolution`).

## Findings that may disappear

All with `--index-store-path`:

- A declaration that only a `#Preview` body names: `user0` in a preview file, `makeShredSelectionModelForPreview`,
  `previewSampleToolbarIconNames`. They were false positives. One that is also used by name in a preview of another type
  (`isSelected`, `pageTitle`, `bodyLarge` on the reference app) is kept alive by that name.
