# deadwood 0.16.0 (from 0.15.4)

The index path reports what it used to hide, and no longer reports what a partial or reused index store made look dead. Without
`--index-store-path` two things change: how deadwood reads what a type conforms to, and what that exempts.

Four causes, all in how a declaration is matched to the compiler's record and what is done where the record has nothing:

1. A declaration whose line the index puts more than five lines away (the source moved after the build, or the store keeps the
   units of an earlier build beside the last one) mapped to no symbol. The walk starts from symbols, so an unmapped `body` or
   `main` rooted nothing, and every member it used was reported: `viewModel`, `canCreate…`, `columnSpacing` and others, at
   confidence high. A symbol is now matched at every line the store records it at, and the only declaration of its name in a file is
   matched to its symbol wherever it is.
2. An index written by a build that skipped function bodies (Xcode's "prepare for indexing") has the declarations and few of the
   uses inside them. The uses the source has and the index lacks are now found, by name looked up as Swift looks it up, once the
   declaration that has them is reached from an entry point. A declaration nothing reaches adds nothing.
3. A member that the compiler records as overriding or witnessing a requirement defined outside the analyzed files is kept, wherever
   the conformance is written.
4. What a type conforms to is read through the protocols and superclasses of the analyzed files (`struct S: Entity` with
   `protocol Entity: Hashable` is `Hashable`). This applies without an index too.

On a complete index nothing is added by the second cause: every name the source uses is recorded, and the result is the compiler's.

Measured on the reference app: with a complete index of the modules a scheme builds, the findings are those of 0.15.4 plus two
unused methods it did not report. With an index written by a build that skipped function bodies, 987 findings became 153, three of
them new and unused. Without an index, two unused methods are reported that were not.

## Findings that may appear

- A member of a type whose superclass is declared in the analyzed files, and that only an uncataloged external type used to
  exempt: the superclass is no longer taken for an unknown external type. Without an index too.
- A declaration that a stale or partial index had kept alive because an unmapped declaration rooted its name everywhere: the name
  now stands for the member in scope. With `--index-store-path`.
- A method that nothing calls and that shares its name with a property the code reads (an unused `View` extension method beside a
  `@Environment` property of the same name): the name no longer roots every definition of it. With `--index-store-path`.

## Findings that may disappear

- A member used by a view's `body`, an initializer, a property wrapper's observer or an autoclosure, reported because the index
  placed the use on a line deadwood did not match, or did not record it at all. With `--index-store-path`.
- A type's `hash(into:)`, `description` or other witness of a requirement its protocol inherits from an external protocol. Without
  an index too.
- A member that witnesses a requirement defined outside the analyzed files through a conformance written in another file. With
  `--index-store-path`.
- A type named like an external protocol (a private `enum Layout`) no longer hides the external protocol's requirements.

## Consumer steps

- Locks that list deadwood (swift-ci's built-in tool lock, aemi `Scripts/analyzers.lock`): deadwood 0.16.0 by version and SHA-256.
- Projects that pin the deadwood `.binaryTarget`: this release's bundle and checksum.
- Projects with a baseline written by 0.15: findings that disappear are dropped from the baseline on the next
  `--write-baseline`; the few that appear are reported until fixed or baselined.
- For findings that are the compiler's, analyze a store written by one full build of the commit (see
  [the index store](../docs/index-store.md#partial-indexes)).
