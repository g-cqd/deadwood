# deadwood 0.16.0 (from 0.15.4)

The index path stops reporting what a partial, drifted or reused index store made look dead, and no longer misses what its own
record shows is used. Without `--index-store-path` two things change: how deadwood reads what a type conforms to, and what that
exempts.

Six causes:

1. A declaration whose line the index puts more than five lines away (the source moved after the build, or the store keeps the
   units of an earlier build beside the last one) mapped to no symbol. The walk starts from symbols, so an unmapped `body` or
   `main` rooted nothing, and every member it used was reported at confidence high. A symbol is now matched at every line the
   store records it at, and the only declaration of its name in a file is matched wherever it is. A root that still maps to
   nothing roots what it uses by name.
2. A Swift Testing test is named by a raw identifier that can hold parentheses (`` `default handleState(from:to:) forwards` ``), and
   deadwood cut the index's name at the first one, so such tests mapped to nothing and what they use was reported. Only the
   trailing argument labels are cut now.
3. A unit that could not resolve a type of a member's signature records the member with an error type in its USR, and a call from
   another unit records the resolved one. They never matched, so the member looked uncalled; they share the type and the name, and
   that links them.
4. An index written by a build that skipped function bodies (Xcode's "prepare for indexing") has the declarations and few of the
   uses inside them. The uses the source has and the index lacks, other than names the declaration binds itself, are found by name
   looked up as Swift looks it up, within the module and what its file imports, once the declaration that has them is reached from
   an entry point. A declaration nothing reaches adds nothing.
5. A member that the compiler records as overriding or witnessing a requirement defined outside the analyzed files is kept,
   wherever the conformance is written.
6. What a type conforms to is read through the protocols and superclasses of the analyzed files (`struct S: Entity` with
   `protocol Entity: Hashable` is `Hashable`), and the requirements known for `Sequence` and `OptionSet` include their
   customization points. These two apply without an index too.

On a complete index the fourth cause adds little: a body whose names the index records adds nothing.

Measured on the reference app, against the index of a full build of its unit-test scheme: 151 findings in 0.15.4 and 144 now.
Three are new and unused; ten are no longer reported, each a member the index shows used by a test (nine) or whose only references
are writes. Against an index written by a build that skipped function bodies: 986 findings became 144, and 122 of those 144 are
findings of the full build's index (22 are not, 22 of the full build's are not found). Without an index, two unused methods are
reported that were not.

## Findings that may appear

- A member of a type whose superclass is declared in the analyzed files, and that only an uncataloged external type used to
  exempt: the superclass is no longer taken for an unknown external type. Without an index too.
- A declaration that nothing uses and that 0.15.4 kept alive: on the reference app, a property and two methods, with and without
  an index.

## Findings that may disappear

- A member used by a view's `body`, an initializer, a property wrapper's observer or an autoclosure, reported because the index
  placed the use on a line deadwood did not match, or did not record it at all. With `--index-store-path`.
- A member used only by a Swift Testing test named by a raw identifier with parentheses, and a member called through a signature
  whose type its own unit could not resolve. With `--index-store-path`.
- A property that is only assigned, when the assignment is in an initializer the index shows reached: the index counts a write as a
  use, as 0.15.4 did, and 0.15.4 reported it only when it also failed to reach the initializer. The opt-in `assign-only-property`
  rule is what reports assigned-only properties.
- A type's `hash(into:)`, `description` or other witness of a requirement its protocol inherits from an external protocol, and
  an implementation of a customization point of `Sequence` or `OptionSet`. Without an index too.
- A member that witnesses a requirement defined outside the analyzed files through a conformance written in another file. With
  `--index-store-path`.
- A type named like an external protocol (a private `enum Layout`) no longer hides the external protocol's requirements.

## Consumer steps

- Locks that list deadwood (swift-ci's built-in tool lock, aemi `Scripts/analyzers.lock`): deadwood 0.16.0 by version and SHA-256.
- Projects that pin the deadwood `.binaryTarget`: this release's bundle and checksum.
- Projects with a baseline written by 0.15: findings that disappear are dropped from the baseline on the next
  `--write-baseline`; the few that appear are reported until fixed or baselined.
- For findings that are the compiler's, analyze a store written by one full build of the commit (see
  [the index store](../docs/index-store.md#partial-indexes)).
