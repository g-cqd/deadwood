# deadwood 0.14.2 (from 0.13.1)

The tags v0.14.0 and v0.14.1 exist but were never published: their Linux build did not compile (the branch for a platform without IndexStoreDB returned a pair where a triple is declared), so this release is the first of 0.14, and this note is the sum of both. Builds on aemi `a4e7edc`, AemiRegex `b4a058f`, AemiJSON `f03e42f`, AemiProtobuf `9af5a96` and analyzerkit `df47839`, which the tools pin together (analyzerkit ADR-0025).

Two declarations reported unused without a store are reached too, found by running the five analyzers on each other's repositories (both gaps are older than 0.14): an extension of a nested type, and `validate()` of a command.

## Findings that may disappear

All with `--index-store-path`:

Without an index store (the same on 0.13.1):

- A member of `extension Outer.Inner` (or `extension Module.Outer.Inner<Int>`) and what it reads. The extension was named by its
  whole spelling, so a reference to `Inner` did not reach it, and an initializer written in such an extension was never
  followed. Seen on swift-search (`extension SearchWorkspace.Options { init(input:…) }`, which read `excludePaths`). The
  extension is now also known by the last component of the type it extends. Without an index store; 0.13.1 and 0.14.0 had the
  same gap.
- `validate()` of a `ParsableCommand` or `AsyncParsableCommand`. ArgumentParser calls it; only types that named
  `ParsableArguments` themselves were known to.
